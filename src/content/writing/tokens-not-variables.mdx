很多人第一次接触设计令牌，是看到一份 `:root { --color-primary: #4d6bfe; }` 这样的清单。于是「引入令牌」被理解成「把颜色换成变量」——三个月后，主题改不动，深色模式里总有几块颜色漏掉，最后又回去硬编码。

问题不在变量，在**分层**。

## 原色、语义、组件，三层不能混

一个能活过两年的令牌系统，通常有明确的三层：

1. **原色层（static）**：调色板的原始取值，`--dsw-static-deepseek-500`。这一层允许被引用，但不允许在组件里直接用。
2. **语义层（alias）**：说明用途，`--dsw-alias-label-primary`、`--dsw-alias-bg-layer-1`、`--dsw-alias-border-l2`。组件只准用这一层。
3. **组件/状态层（specific）**：某个控件特有的值，比如气泡背景 `--dsw-specific-bubble`。

分层的好处是，换肤时你只需要重新映射第二层：

```css
/* 语义层只做映射，不写死取值 */
:root {
  --dsw-alias-bg-base: var(--dsw-static-neutral-bluish-00);
  --dsw-alias-label-primary: var(--dsw-static-neutral-bluish-1000);
}

body[data-ds-dark-theme] {
  --dsw-alias-bg-base: var(--dsw-static-neutral-bluish-950);
  --dsw-alias-label-primary: var(--dsw-static-neutral-bluish-50);
}
```

组件里写的是 `color: var(--dsw-alias-label-primary)`。于是「明暗两套主题」变成了一份组件代码加两份映射，而不是两套组件。

如果组件里出现 `#4d6bfe` 或者 `--dsw-static-deepseek-500`，那就是漏网之鱼。这条规则可以用一个正则 CI 检查掉，比口头约定可靠。

## 令牌只负责不变量

令牌适合装的是那些**跨页面、跨主题、跨版本都不应该变**的东西：颜色语义、间距阶梯、圆角半径、阴影层级、动效曲线。

它不适合装：

- **业务数据**。价格、用户名、句子长度，这些不是设计决策。
- **一次性的布局数值**。`grid-template-columns: 3.25rem 1fr 1.5rem` 里的 3.25rem 不值得成为令牌，它就是这一行布局的一部分。
- **还没有收敛的表达式**。一个变量只被用过一次的时候，它只是给读者增加了一次跳转。

DSH 的令牌表就遵守这个边界：它有完整的色阶、字号阶梯、阴影和缓动，但字号最大只到 24px——因为它服务的是 12–17px 的应用界面。拿它做营销页，标题层必须自己补一套显示级字阶，这是**预期内**的事，不是令牌不够用。

## 明暗主题要由运行时管，而不是靠媒体查询

只靠 `@media (prefers-color-scheme: dark)` 会卡在三个地方：用户手动切换不生效、首帧闪白、`meta[name=theme-color]` 不跟随。

一个够用的主题运行时其实只有几件事：

- 存偏好（`light` / `dark` / `system`）
- 监听系统主题变化，只在 `system` 模式下重新计算
- 把结果投影到 DOM：`color-scheme`、`body` 上的调色板属性、`meta theme-color`

这个站点用的就是 DSH 的 `ThemeRuntime` 加 `ThemePresenter`，四十行左右的 DOM 操作，没有 React，也没有状态库。核心是把「读环境」和「写 DOM」分开：运行时从不碰 DOM，presenter 从不判断主题。

> 判断标准：如果你不能在测试里构造一个快照、断言 DOM 属性，那这套主题逻辑就是耦合的。

## 一条可执行的检查清单

- 组件样式里搜索 `#`、`rgb(`、`hsl(`，只允许出现在令牌文件里。
- 语义层每个令牌都要在明暗两套里都有值，缺一个就是一个未来的 bug。
- 删除任何一个令牌之前，先搜一遍有没有组件在用它。
- 令牌文件本身要能被单独打包、单独版本化，而不是混在 `global.css` 的五百行里。

做到这四条，令牌才真的是资产，而不是一层没人维护的间接引用。
